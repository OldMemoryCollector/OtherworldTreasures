# SCP-294 药水显示与奖励预生成验证（2026-10-21）

修正可消耗能量牌中的“耗能”误匹配，保留独立的“耗能”和“能量”关键词高亮。

怪物意图共用玩家药水的配方命名、混合瓶身和完整药效描述，仅替换施用对象的称呼；百分比和数值配色沿用玩家药水。每个招式缓存显示配方，意图、提示图标和实际投出的药瓶使用同一张贴图。生成显示配方使用独立确定性 RNG，刷新界面不推进游戏药水 RNG。

常态模式下，奖励在 Populate 或奖励钩子处理完成时生成最终配方，界面展示和领取使用同一 PotionModel。沿用奖励指定的 RNG 或玩家奖励 RNG；领取时不再重掷。通过原生 SerializableReward.PredeterminedModelId 保存现有 BREW_ 配方 ID，未增加保存或网络协议字段；附魔金苹果的自定义奖励也保留配方和宝箱标识。

配置名已改为“为什么会变成这样呢？（测试中，未完善）”，英文及日文同步标注。

## 验证

隔离的原版游戏进程完成 26 项检查：关键词边界；怪物的完整效果、百分比单位、数值和关键词配色；名称和混合图标；意图与投瓶图像一致；重复刷新不推进游戏药水 RNG；关闭常态模式保留原药水；奖励生成前置且 Populate 不重掷；配方序列化恢复一致；原生奖励图标模型；奖励指定 RNG 的确定性；背包满时领取失败仍保持原配方，腾出栏位后领取同一对象；已填充的自定义奖励与宝箱标识的往返恢复；原生奖励界面展示。

已检查怪物提示和奖励界面的实机截图。主项目构建 0 错误，21 条既有警告。PCK 的 857 项资源 MD5 全部匹配，6 个语言文件与源码逐字节一致。测试探针未安装到正式游戏。宿主退出仍报告既有 RID 和资源清理诊断；未执行两个真实客户端的联机验证，奖励序列化检查不等同于完整双端测试。
